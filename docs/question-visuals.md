# Compact question visuals and explicit AI illustrations

The optional-visual checkbox now requests `diagramRelevance` (helpful boolean plus a brief reason) for each AI question. It does not embed diagrams in the generation response. Relevance metadata is bounded and normalised separately; unexpected/invalid optional diagrams are removed before validating the quiz. This prevents optional artwork validation from rejecting otherwise valid questions and reduces output size. Existing question validity, quota refunds, retry deduplication and provider/budget failure handling remain enforced.

Evidence: recent production logs included POST `/api/ai/generate` returning HTTP 400 at 2026-10-12 08:39:24 UTC, request c6581659da960b28ed3421c34ae9e9fe. The retained event did not contain the application error text, so it cannot prove which validation failed. Code inspection identified that inline optional diagram validation could fail the entire request; regression tests reproduce invalid optional visual isolation after the fix.

Every question exposes two compact, labelled icon buttons: upload/edit a picture and create/edit an AI diagram. Only the selected tool expands. Attached visuals are indicated with a small dot. Relevance notes appear in the AI preview and creator editor, with reasons. Uploaded images retain existing resizing, access controls and accessibility description requirements.

An explicit description (5–500 characters) requests a non-null diagram, even if automatic relevance says no. Simple counting/shape/fraction/bar/flow types remain compatible. A new illustration type contains a limited set of paths, ellipses, rectangles, lines and text on a 600×400 canvas. It supports simplified educational caricatures and labelled sketches beyond the previous geometric-only types. The renderer never accepts raw SVG/HTML, script, URLs or external images. Paths, palettes, element counts, numeric coordinates and string lengths are validated; React escapes labels. Accessibility uses a title and description.

Generation uses the existing metered GPT-4.1-mini text endpoint with at most 5,000 output tokens and one call, rather than a raster image-generation endpoint. There is no extra question-credit deduction; normal eligibility, rate limits, service spending controls and provider costs still apply. Explicit requests cannot return the 'would not help' skip state, though provider/network failures, refusals, invalid outputs or service limits can still require a retry. Accuracy and completeness must be reviewed by the creator; a lightweight drawing is not a guarantee of technical/anatomical fidelity.

Creator and student answer tiles use purple, mint, yellow and orange, plain letters and a visible non-colour selection state. Creator correct-answer selection is an accessible pressed tick button rather than an additional radio circle. Question cards have a simple border and no decorative shadow. New styles are imported after the existing interior stylesheet so they do not get overridden; homepage styling and logo are preserved.

Validation: existing API suite, `node tests/illustrations.mjs`, timing/platform/help regression tests, TypeScript and production build. Browser/device visual QA is unavailable in this environment.
