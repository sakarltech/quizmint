# Quiz timing and saved attempts

Creators choose a whole-quiz time limit (1–240 minutes) or Untimed. The database default is zero, preserving existing quizzes. AI/import question replacements keep the creator's selected timing; public library copies preserve the published timing. Arena uses its independent per-round timer.

All real student attempts start through `/api/quiz/[id]/session`. A 256-bit random bearer token is returned once and only its SHA-256 digest is stored. Resume tokens travel in POST bodies; a private cross-device resume link carries the token in the URL fragment, removed immediately on opening. Email alone cannot retrieve an attempt. Browser storage keeps the token and a pending answer backup, with no automatic untimed expiry. Closing/deleting the parent quiz blocks access; reopening restores unfinished attempts, subject to the original timed deadline. Quiz deletion deletes saved attempts and results.

The immutable attempt snapshot contains the question set and timing. Public start/resume/save responses exclude answer keys and explanations until completion. Saves use revision compare-and-swap to avoid stale-tab overwrites. Submissions atomically store a result and one creator-visible attempt; retries return the saved result. Timed quizzes reject the legacy direct submission API. The deadline is checked both in the application and with the database clock before accepting saves or on-time submissions. At expiry, only already-persisted answers are graded; unanswered questions score zero. Finalisation occurs when the connected client observes expiry or a future resume/save/submit reaches the server, rather than through a scheduled background task.

The client serialises autosaves, keeps a pending same-browser backup and retries on connection restoration. It shows save status, warns before leaving with pending answers and provides an explicit Save & leave control for untimed attempts. A copied resume link offers cross-device access. This is an online persistence feature, not a promise of offline quizzes or recovery after losing every token. Browser timer presentation uses monotonic elapsed time anchored to the server clock; the server remains authoritative. Creator-chosen timings should suit learner access needs.

Security limitations: student emails are self-reported; private links are bearer credentials and should not be shared. Open quiz links permit additional new attempts rather than verified one-attempt-per-person enforcement. In-progress answers are not made public or placed in creator results until submitted. Start requests are bounded to 300 per quiz/network per 15 minutes, allowing shared school networks while limiting accidental start loops. A connected client makes a bounded retry attempt every 10 seconds after expiry if the network is unavailable.

Validation: `node tests/quiz-timing.mjs`, existing API/platform/help/password-reset suites, TypeScript and the Sites production build. Browser/device visual QA is unavailable in this environment.
